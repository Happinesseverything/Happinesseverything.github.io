常用字段类型对照表

Oracle 类型少，靠参数控制精度；MySQL 类型多，选型要看范围和存储

用途 Oracle MySQL 说明 / 坑点
整数（常规） NUMBER(10) INT Oracle 没有 INT，整数全靠 NUMBER(n) 的位数表达范围
小整数 / 大整数 NUMBER(3) / NUMBER(19) TINYINT / BIGINT MySQL 细分 TINYINT(-128~127)、SMALLINT、MEDIUMINT、INT、BIGINT，选小了会溢出

Oracle 选型速记

类型就那么几个：数字全用 NUMBER、字符串全用 VARCHAR2、日期全用 DATE。 不用纠结选哪种整数，用位数说话：NUMBER(3) 存状态、NUMBER(10) 存 ID、NUMBER(19) 存大数。

MySQL 选型速记

类型很多，选之前想两件事：范围够不够（TINYINT 上限只有 127）、按字符还是按字节。 字符串长度 VARCHAR(n) 的 n 是字符数，中文不用担心超长——这点和 Oracle 相反。

03

Oracle 最容易踩的坑

都是从 MySQL 切过来、或者刚上手 Oracle 时一定会撞上的东西，按踩到的概率排序

坑 1= NULL 永远查不出东西 高频坑

NULL 不是"空值"，而是"未知"。未知和任何东西比较都得不到真，所以 = NULL 永远为假。

Oracle
-- 错：查不出任何行，而且不报错
SELECT * FROM emp WHERE comm = NULL;

-- 对：
SELECT * FROM emp WHERE comm IS NULL;
SELECT * FROM emp WHERE comm IS NOT NULL;

-- 更隐蔽的：不等于号会把 NULL 行一起丢掉
SELECT * FROM emp WHERE comm <> 0;        -- comm 为 NULL 的人不在这里面
SELECT * FROM emp WHERE comm <> 0 OR comm IS NULL;   -- 想带上 NULL 就得这么写

记住：凡是可能为空的列，条件里都要单独考虑 NULL，尤其用 <>、NOT IN 的时候。NOT IN 里如果有 NULL，整条查询会返回空。

坑 2空字符串 '' 在 Oracle 里就是 NULL 高频坑

Oracle 里 '' 和 NULL 是同一个东西——这是 Oracle 独有的设计，MySQL 里它们是两码事。

Oracle
-- 这两句查出来的结果是一样的
SELECT * FROM emp WHERE emp_name IS NULL;
SELECT * FROM emp WHERE emp_name = '';

-- 插进去的空串，存下来就是 NULL
INSERT INTO emp (emp_name) VALUES ('');
SELECT * FROM emp WHERE emp_name IS NULL;   -- 能查到

-- 判空函数也认为空串是空值
SELECT NVL('', '默认值') FROM DUAL;         -- 返回「默认值」

-- 想区分「没填」和「填了个空」，得自己约定一个特殊值
INSERT INTO emp (emp_name) VALUES ('-');

影响：从 MySQL 迁过来的数据，原本是空串的字段全变成 NULL，WHERE 字段 = '' 一句都查不到。设计表时直接规定：不想为空就加 NOT NULL 约束。

坑 3字符串用了双引号，报「标识符无效」 高频坑

ORA-00904 是新手见最多的错，八成是引号用错了。

Oracle
-- 错：ORA-00904: "张三": 标识符无效
SELECT * FROM emp WHERE emp_name = "张三";

-- 对：字符串只能用单引号
SELECT * FROM emp WHERE emp_name = '张三';

-- 字符串里有单引号，用两个单引号转义
SELECT 'it''s ok' FROM DUAL;      -- 结果：it's ok
SELECT 'it\'s ok' FROM DUAL;      -- 错！Oracle 不认反斜杠转义

记住：单引号 = 字符串，双引号 = 字段名（而且区分大小写）。MySQL 里双引号通常是字符串，所以从 MySQL 抄过来的 SQL 会在这里报错。

坑 4改完数据忘了 COMMIT 高频坑

Oracle 默认不自动提交。改完不提交，你自己看着是改好了，别人却完全看不到——排查半天以为是数据没同步。

Oracle
UPDATE emp SET salary = 9000 WHERE emp_id = 1;
-- 此时你自己查是 9000，别的会话查还是旧值

COMMIT;      -- 提交，改动才真正生效

-- 反悔
ROLLBACK;    -- 撤销本次所有未提交的改动

-- 关掉窗口 / 断开连接 → 未提交的改动全部自动回滚

在 PLSQL Developer 里：改完点工具栏的 ✓（或按 F10）才是提交，那个绿色箭头只是执行。养成习惯：写操作执行完立刻 COMMIT。

坑 5UPDATE / DELETE 忘了写 WHERE 高频坑

整表被改、整表被删，是新人最容易造成的重大事故，而且一旦提交就回不来了。

Oracle
-- 三步走，别跳步
-- 第一步：先备份（尤其是正式环境）
CREATE TABLE emp_bak_20260920 AS SELECT * FROM emp;

-- 第二步：把要改的条件当 SELECT 跑一遍，核对行数
SELECT COUNT(*) FROM emp WHERE dept_id = 10;

-- 第三步：确认无误再改
UPDATE emp SET status = 0 WHERE dept_id = 10;
COMMIT;

-- 万一忘了写 WHERE 又还没提交
ROLLBACK;    -- 立刻回滚，还来得及

兜底：如果不小心提交了，可以用 AS OF TIMESTAMP 闪回查询抢救（前提是撤销表空间够大、时间没过太久）： SELECT * FROM emp AS OF TIMESTAMP (SYSTIMESTAMP - INTERVAL '10' MINUTE);

坑 6DDL 会自动提交，事务兜不住 高频坑

以为"没提交就还能回滚"，结果中间夹了一句建表语句，前面的改动全被一起提交了。

Oracle
INSERT INTO emp (emp_id, emp_name) VALUES (1, '张三');
CREATE TABLE t_tmp (id NUMBER);   -- 这一句把上面的 INSERT 一起提交了
ROLLBACK;                          -- 已经晚了，回不去

-- 会自动提交的语句：
-- CREATE / ALTER / DROP / TRUNCATE / RENAME / GRANT / REVOKE / COMMENT

做法：做完一批数据改动就先 COMMIT，再执行 DDL。别让数据操作夹在结构变更中间。

坑 7TRUNCATE 不能回滚，DROP 反而还能救

听起来反直觉：删表进回收站能捞回来，清空表反而是彻底没了。

Oracle
TRUNCATE TABLE emp;      -- 清空，DDL，不能 ROLLBACK，也不能 FLASHBACK
DROP TABLE emp;          -- 进回收站，还能救
FLASHBACK TABLE emp TO BEFORE DROP;           -- 捞回来
SELECT * FROM USER_RECYCLEBIN;                -- 看回收站里有什么

DROP TABLE emp PURGE;    -- 加 PURGE 才是彻底删除，不进回收站

结论：要清数据先想清楚，TRUNCATE 是没法后悔的。日常清理优先用 DELETE + WHERE（可回滚），确认没问题再 TRUNCATE。

坑 8VARCHAR2 的长度默认按字节算 高频坑

声明 10 个字符，插 4 个汉字就报 ORA-12899——因为 SQL 里写着 10，实际只放得下 3 个汉字。

Oracle
-- 错：UTF-8 下中文占 3 字节，VARCHAR2(10) 只放得下 3 个汉字
CREATE TABLE t (name VARCHAR2(10));

-- 对：加 CHAR 后缀，明确按字符算
CREATE TABLE t (name VARCHAR2(10 CHAR));   -- 能放 10 个汉字

-- 查当前库默认是按字节还是按字符
SELECT * FROM NLS_DATABASE_PARAMETERS WHERE PARAMETER = 'NLS_LENGTH_SEMANTICS';
-- 值 BYTE = 按字节，CHAR = 按字符

建议：建表时一律写 VARCHAR2(n CHAR)，多打 5 个字符，少踩一堆坑。MySQL 的 VARCHAR(n) 天生按字符算，不用管这事。

坑 9DATE 含时分秒，等值查询会漏数据 高频坑

Oracle 的 DATE 是"日期 + 时间"，= to_date('2026-09-20') 只匹配当天 00:00:00 那一瞬间，当天的数据基本都查不到。

Oracle
-- 错：只能匹配到 00:00:00，白天录入的数据一条都查不到
SELECT * FROM emp WHERE hire_date = TO_DATE('2026-09-20', 'YYYY-MM-DD');

-- 对：用左闭右开区间
SELECT * FROM emp
WHERE hire_date >= TO_DATE('2026-09-20 00:00:00', 'YYYY-MM-DD HH24:MI:SS')
  AND hire_date <  TO_DATE('2026-09-21 00:00:00', 'YYYY-MM-DD HH24:MI:SS');

-- 也可以用 TRUNC 截掉时分秒，但会让索引失效（数据量大时慢）
SELECT * FROM emp WHERE TRUNC(hire_date) = TO_DATE('2026-09-20', 'YYYY-MM-DD');

记住：查某一天的数据，统一用 >= 当天 AND < 次日 的写法，既准又快。

坑 10ROWNUM 是在排序前生成的 高频坑

想取"金额最高的 10 笔"，直接 WHERE ROWNUM <= 10 ORDER BY 金额 DESC，拿到的其实是随便 10 笔再排序。

Oracle
-- 错：先取前 10 行（顺序随机），再对这 10 行排序
SELECT * FROM emp WHERE ROWNUM <= 10 ORDER BY salary DESC;

-- 对（11g 及以前）：先排序，再套一层取行号
SELECT * FROM (SELECT * FROM emp ORDER BY salary DESC) WHERE ROWNUM <= 10;

-- 对（12c 起，推荐）：
SELECT * FROM emp ORDER BY salary DESC FETCH FIRST 10 ROWS ONLY;

-- 想跳过前面几行（分页），只能套三层
SELECT * FROM (
  SELECT t.*, ROWNUM rn FROM (SELECT * FROM emp ORDER BY salary DESC) t
  WHERE ROWNUM <= 30
) WHERE rn > 20;

一句话：ROWNUM 是"取到第几行"的编号，跟排序没关系。要"排序后再编号"，用 ROW_NUMBER() OVER (ORDER BY ...)。

坑 11表别名不能加 AS

从 MySQL 抄 SQL 过来最常报的错之一，报错信息是 ORA-00933 而不会告诉你"AS 写错了"。

Oracle
-- 错：ORA-00933: SQL 命令未正确结束
SELECT * FROM emp AS e WHERE e.emp_id = 1;

-- 对：表别名直接跟在表名后面，中间不要 AS
SELECT * FROM emp e WHERE e.emp_id = 1;

-- 列别名可以加 AS，也可以不加
SELECT emp_name AS name, salary annual FROM emp e;

技巧：看到 ORA-00933，先检查表别名后面是不是多了个 AS。

坑 12加了双引号的字段名区分大小写

Oracle 默认把不带引号的名字转成大写；一旦用双引号建成了小写名，之后不带引号就永远查不到。

Oracle
CREATE TABLE t (
  "empNo" NUMBER(10),   -- 用双引号建成了「小写 n」的名字
  empno   NUMBER(10)    -- 不带引号，实际存成大写 EMPNO
);

-- 这两列在 Oracle 眼里是不同的名字！
SELECT "empNo" FROM t;   -- 对
SELECT empno   FROM t;   -- 不带引号 → 找的是 EMPNO，是另一列
SELECT EMPNO   FROM t;   -- 对，等价于上一句

-- 查表里真实的列名
SELECT column_name FROM user_tab_columns WHERE table_name = 'T';

建议：建表建列一律不用双引号，大小写随意写，Oracle 会统一存成大写。只有必须带空格/特殊字符的名字才用引号，那种情况很少见。

坑 13Oracle 没有 BOOLEAN 字段类型

建表时想加个"是否启用"的布尔列，Oracle 会告诉你没有这个类型。

Oracle
-- 错：ORA-00902: 数据类型无效
CREATE TABLE t (is_active BOOLEAN);

-- 对：用 NUMBER(1) 或 CHAR(1)，再加约束卡住取值范围
CREATE TABLE t (
  is_active NUMBER(1) DEFAULT 1 CHECK (is_active IN (0, 1))
);

-- 查询时就是普通数字，不能写 WHERE is_active = TRUE
SELECT * FROM t WHERE is_active = 1;

说明：BOOLEAN 只在 PL/SQL 代码里有（存储过程、函数内部可以声明布尔变量），SQL 语句和表结构里都没有。MySQL 的 BOOLEAN 其实是 TINYINT(1) 的别名，能用。

坑 14除以零直接报错

ORA-01476: 除数为 0。做比率、占比计算时经常撞上，MySQL 里这种情况只是返回 NULL，不报错。

Oracle
-- 错：ORA-01476: 除数为 0
SELECT salary / bonus FROM emp;

-- 对：用 NULLIF 把 0 变成 NULL（除数是 NULL 时结果也是 NULL，不报错）
SELECT salary / NULLIF(bonus, 0) FROM emp;

-- 对：用 CASE 显式兜底
SELECT CASE WHEN bonus = 0 THEN NULL ELSE salary / bonus END FROM emp;

-- 想要 0 而不是 NULL，再套一层
SELECT NVL(salary / NULLIF(bonus, 0), 0) FROM emp;

记住：凡是做除法，分母都用 NULLIF(列, 0) 包一层，这是最省事的写法。

坑 15隐式类型转换让索引失效

字段是字符串类型，条件里写了数字——Oracle 会把整列的字符串转成数字再比，索引就用不上了，大表上慢到怀疑人生。

Oracle
-- 假设 emp_no 是 VARCHAR2，并且建了索引
-- 错：列被隐式转成数字，索引失效，全表扫描
SELECT * FROM emp WHERE emp_no = 1001;

-- 对：保持类型一致
SELECT * FROM emp WHERE emp_no = '1001';

-- 同理，这些都会失效：
SELECT * FROM emp WHERE UPPER(emp_name) = 'ABC';          -- 列上套了函数
SELECT * FROM emp WHERE TO_CHAR(hire_date, 'YYYY') = '2026';
SELECT * FROM emp WHERE SUBSTR(emp_no, 1, 3) = '001';

-- 想看看到底走没走索引，看执行计划
EXPLAIN PLAN FOR SELECT * FROM emp WHERE emp_no = '1001';
SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);

原则：WHERE 里让列保持"裸露"——别在列上套函数、别改它的类型。真需要函数查询，就建函数索引。

坑 16GROUP BY 的列必须写全

Oracle 在这方面比 MySQL 严格得多，会直接报 ORA-00979 拒绝执行。

Oracle
-- 错：ORA-00979: 不是 GROUP BY 表达式
SELECT dept_id, emp_name, SUM(salary)
FROM emp
GROUP BY dept_id;

-- 对：要么放进 GROUP BY，要么套聚合函数
SELECT dept_id, MIN(emp_name), SUM(salary)
FROM emp
GROUP BY dept_id;

-- 想做「每个部门薪水最高的人」，别用 GROUP BY，用窗口函数
SELECT * FROM (
  SELECT dept_id, emp_name, salary,
         ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) rn
  FROM emp
) WHERE rn = 1;

顺带：MySQL 老配置里这样写能跑出结果，但取到的 emp_name 是随机的，比报错更危险。看到别人这么写，结果可信度要打个问号。

坑 17排序时 NULL 跑到了最前面

做"按金额降序"的排行榜，排在第一的是金额为空的那几条，看着像数据错了，其实是 Oracle 的默认行为。

Oracle
-- Oracle 默认：ASC 时 NULL 排最后，DESC 时 NULL 排最前
SELECT emp_name, comm FROM emp ORDER BY comm DESC;

-- 显式控制（Oracle 独有语法）
SELECT emp_name, comm FROM emp ORDER BY comm DESC NULLS LAST;   -- 空值排最后，报表常用
SELECT emp_name, comm FROM emp ORDER BY comm ASC  NULLS FIRST;

-- 空值换成默认值再排，效果类似
SELECT emp_name, NVL(comm, 0) comm FROM emp ORDER BY NVL(comm, 0) DESC;

记住：凡是排序的列可能为空，都显式加一句 NULLS LAST，省得被报表结果吓一跳。

坑 18没提交的改动会把别人卡住

你在一个窗口改了某行但没提交，另一个窗口改同一行就会一直转圈——这是行锁，不是系统坏了。

Oracle
-- 会话 A
UPDATE emp SET salary = 9000 WHERE emp_id = 1;   -- 不提交

-- 会话 B 执行同样的语句 → 一直等待，直到 A 提交或回滚

-- 找谁在占锁（需要权限）
SELECT s.sid, s.serial#, s.username, s.event, s.blocking_session
FROM v$session s
WHERE s.blocking_session IS NOT NULL;

-- 确认清楚后，可以杀掉那个会话（谨慎！）
ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;

习惯：改完数据立刻 COMMIT 或 ROLLBACK，别把事务开着去干别的事。忘了关的工具窗口，是同事抱怨"数据库卡了"的常见原因。

坑 19(+) 外连接的两条硬规矩

接手老系统一定会遇到 (+) 写法，它有两条限制，不知道就会写出报错的 SQL。

Oracle
-- 正确：(+) 只能加在「可能缺数据」的那一侧
SELECT * FROM emp e, dept d
WHERE e.dept_id = d.dept_id(+);      -- 等价 LEFT JOIN

-- 错：ORA-01468，(+) 不能两边都加
SELECT * FROM emp e, dept d
WHERE e.dept_id(+) = d.dept_id(+);

-- 错：(+) 不能和标准 JOIN 混着写
SELECT * FROM emp e LEFT JOIN dept d ON e.dept_id = d.dept_id(+);

-- 多表外连接的 (+) 要写全，漏一个就变成内连接了
SELECT * FROM a, b, c
WHERE a.id = b.aid(+) AND a.id = c.aid(+);

建议：新写 SQL 一律用标准 LEFT JOIN；读老代码时看到 (+) 就翻译成"这一侧的表可能没数据"。漏写 (+) 会让外连接悄悄退化成内连接，少数据还不报错。

坑 20字符集与中文乱码

插进去的中文变成乱码或问号，一般是客户端和数据库的字符集对不上，跟数据本身没关系。

Oracle
-- 看数据库的字符集（应该是 AL32UTF8 或 ZHS16GBK）
SELECT * FROM NLS_DATABASE_PARAMETERS WHERE PARAMETER LIKE '%CHARACTERSET%';

-- 看当前会话的字符集
SELECT * FROM NLS_SESSION_PARAMETERS WHERE PARAMETER LIKE '%CHARACTERSET%';

-- 检查某个值到底是乱码还是显示问题
SELECT DUMP(emp_name, 1016) FROM emp WHERE emp_id = 1;   -- 16 进制看真实字节

排查顺序：① 数据库字符集 → ② 客户端 NLS_LANG 环境变量 → ③ 工具（PLSQL Developer）的连接编码设置。三者必须一致，通常是客户端设成 SIMPLIFIED CHINESE_CHINA.AL32UTF8 或 ZHS16GBK。
